# Desktop renderer performance pass (2026-10-14)

Branch `revamp/w5`. All numbers come from a production renderer build
(`npx vite build` from `apps/desktop`, same config `npm run build` uses for the
renderer), measured from `dist/`.

How it was measured: the entry script and every `<link rel="modulepreload">`
in `dist/index.html` are summed by file size (KiB, 1 KiB = 1024 bytes); gzip
sizes come from Node's `zlib.gzipSync` at the default level. "Boot JS" is the
entry plus every preload: all of it is fetched and parsed before first paint.
The task brief's baseline (6.49 MB preload, 3.81 MB entry) is the same
quantity in decimal megabytes.

## Before and after

| Metric | Before | After | Change |
|---|---|---|---|
| Entry `index-*.js` raw | 3716.5 KiB | 3717.6 KiB | +1.1 KiB |
| Entry `index-*.js` gzip | 1160.2 KiB | 1160.5 KiB | +0.3 KiB |
| Entry CSS `index-*.css` raw / gzip | 434.9 / 71.9 KiB | 434.9 / 71.9 KiB | none |
| Modulepreload count | 171 | 173 | +2 (small split chunks) |
| Modulepreload bytes raw | 6333.2 KiB | 3631.4 KiB | **-42.7%** |
| Modulepreload bytes gzip | 2094.8 KiB | 1234.9 KiB | -41.0% |
| Boot JS (entry + preloads) raw | 10049.8 KiB | 7348.9 KiB | -26.9% |
| Total JS chunks in `dist/assets` | 1091 | 1106 | +15 (one per lazy locale/module) |
| Rail click to Settings (dev) | 133 ms | not re-measured | see "Route switches" |

The largest boot preload before this pass was `storage-*.js` at 2532 KiB.
It held every non-English locale catalog. After the pass, the largest boot
preloads are `sdk-*` (510 KiB), `vendor-md` (341 KiB), `en-*` (295 KiB),
`version-details-*` (279 KiB) and `katex` (253 KiB).

The build still emits a single react-query runtime. Exactly one chunk,
`vendor-react-*`, contains the "No QueryClient set" error string, and
`node scripts/assert-dist-built.mjs` passes. `node --experimental-vm-modules
scripts/check-chunks-parse.mjs dist/assets` parses all 1106 chunks.
`vite.config.ts` was not changed, so the `advancedChunks` "shared foundations
first" groups are intact.

## Changes

### 1. Non-English catalogs load on demand (`src/i18n/catalog.ts`)

`catalog.ts` used to import all nine locale catalogs statically. Rolldown
merged the eight non-English ones into one 2.5 MB shared chunk, so every launch
fetched and parsed them all to render a single language. English is still
static because every lookup falls back to it. The other locales are now
`import()` loaders behind `loadBundledLocale(id)`, which fetches each catalog
once and shares the promise while the fetch is in flight. `I18nProvider` waits
for the catalog before it switches locale, both for the saved
`display.language` and when the user picks a language, so the UI changes
straight to the new language without an English flash. If a module-level
translator asks for a catalog that has not loaded yet, it gets English, the
fetch starts, and `$appLocaleVersion` is bumped when the fetch lands so every
translator re-resolves. `TRANSLATIONS` now holds only the catalogs that have
loaded. `vitest.setup.ts` preloads all of them, so existing tests that index
`TRANSLATIONS` still work. New test: `src/i18n/catalog-lazy.test.ts`.
Result: preload 6333 KiB to 4147 KiB.

### 2. CodeMirror loads on first use (`src/components/chat/code-editor.tsx`)

`CodeEditor` is reachable from always-mounted chrome: the profile switcher and
the preview pane (through `preview-file`). That pulled `@codemirror/*` and the
language table onto the boot path. The implementation moved to
`code-editor-impl.tsx` unchanged. `code-editor.tsx` is now a `Suspense`
wrapper around a `lazy()` import, with an empty placeholder that takes the same
`className`. The props and the `CodeEditorApi` type are re-exported, so call
sites did not change. One test (`preview-file-save-scope.test.tsx`) now waits
for `.cm-content` instead of querying it right after the click. Result:
preload 4147 KiB to 3828 KiB.

### 3. Main route chunks are warmed when the renderer is idle (`src/app/route-chunks.ts`)

Settings, cron, artifacts, capabilities and messaging now use shared loader
functions. Their `lazy()` definitions in `contrib/wiring.tsx` and
`contrib/surfaces.tsx` call these loaders, and so does `warmRouteChunks()`.
`main.tsx` calls `warmRouteChunks()` after the window `load` event, in the main
window only. It loads one chunk per `requestIdleCallback` slot, with a 4 s
timeout and a `setTimeout` fallback, so the first rail click mounts from the
module cache instead of waiting for a fetch and parse. A failed warm fetch is
ignored, because the route's own `lazy()` retries the fetch and shows the error
UI on click. Boot preload bytes did not change, and the route chunks are still
not preloaded. The shell's keep-alive lifecycle was not touched. New test:
`src/app/route-chunks.test.ts`.

### 4. Two always-mounted subscriptions are narrower (`contrib/wiring.tsx`, `chat/sidebar/watch-strip.tsx`)

The desktop controller (`ContribWiring`) subscribed to the whole
`$messagingSessions` list just to compute one boolean (`activeIsMessaging`).
Because that list refreshes on a poll, every poll re-rendered the whole
controller. The controller now reads the boolean through
`useStoresSelector([$messagingSessions, $selectedStoredSessionId], ...)`. The
sidebar watch strip is always mounted and is usually empty, but it subscribed
to three session lists. It now returns before subscribing when nothing is
watched. New test: `src/app/chat/sidebar/watch-strip.test.tsx`.

IPC audit (no change needed): window geometry persistence
(`electron/window-state.ts`) already uses a trailing debounce and flushes on
close. Composer draft stashes are already debounced. The terminal slot tracker
coalesces through rAF. The chat-room resize guard already uses a 150 ms
trailing debounce. Window chrome state is pushed only on discrete events
(maximize, fullscreen, show and hide). I found no high-frequency
renderer-to-main IPC call that was not already coalesced.

### 5. Link brand glyphs load with the first link that shows one (`src/lib/external-link.tsx`)

`LinkBrandIcon` imported the brand table statically. The table holds about 150
Simple Icons, and links render from always-mounted chrome, so the whole table
was a boot preload. `LinkBrandIcon` now renders a lazy `BrandGlyph` from
`lib/brand-glyph.tsx` inside a `Suspense` boundary whose fallback is `null`.
Icons that other boot surfaces import directly (platform icons, connector
logos) stay on the boot path because those surfaces need them. Result:
preload 3828 KiB to 3631 KiB.

## Next candidates (not done)

- **KaTeX (253 KiB).** It is reached through `markdown-text.tsx` and
  `lib/katex-memo.ts`. Streamdown runs rehype with `runSync`, so the math
  transform cannot await an import. Making KaTeX lazy needs a re-render
  trigger: an atom that flips when `katex` lands and feeds the `plugins` memo
  in `MarkdownTextSurface`, which mirrors `useCodePlugin`. The import would
  start only when the transform sees a math node, and the transform would
  leave math nodes as source text until then. `file-preview-math.render.test.tsx`
  renders Streamdown with a static plugin, so it would need the same trigger.
- **`sdk-*` (510 KiB).** This is a merged chunk that the entry shares with the
  bundled plugins (`agentcraft`, `hermes-bots`, `kanban`) through
  `src/sdk/index.ts`. It includes the capabilities tabs and the model catalog
  menu, which the boot path does not need.
- **`profile-ops-*` (174 KiB).** About 116 KiB of it is
  `plugins/hermes-bots/i18n.ts`, which holds four locales of plugin strings.
  It needs per-locale bundles in the plugin i18n API.
- **Onboarding overlay (about 70 KiB, inside `version-details-*`).** It is
  statically imported in `contrib/wiring.tsx` but only shows on first run.
- **Rail click to Settings timing.** It was not re-measured because that needs
  the Electron dev app with a live backend. The idle warmup removes the chunk
  fetch and parse from the first click. Mount cost is unchanged.
