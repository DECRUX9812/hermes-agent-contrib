## 2026-10-20 (later) — the "two products" verdict was wrong; measured fix applied

The 1029-error reading came from one resolution rule, not from product divergence: the tree paired
**main's `en.ts`/`types.ts`** with **branch locale files**. `en.ts` is the type source, so every
branch-only string was an error, and implicit-any cascaded through the locale files.

Method that works (repeatable, verified): **re-run the merge at file granularity with a real 3-way
merge instead of taking a side.**

```
B=$(git merge-base claude/cool-cannon-cx2rw7 origin/main)
git show $B:path > base;  git show claude/cool-cannon-cx2rw7:path > ours;  git show origin/main:path > theirs
git merge-file -L ours -L base -L main ours base theirs   # then resolve the few hunks
```

Across the whole i18n catalog that is **108 files merging clean + 13 files / 22 hunks** — versus the
655 differing values and 629+204 key deltas a side-pick produced.
